# BoxingBot V2.0.1 Hotfix

## Discord modal-flow fix

Discord does not allow a `MODAL_SUBMIT` interaction to respond directly with another modal. V2.0 chained multi-step boxer forms modal-to-modal, so Discord displayed `Something went wrong. Try again.` after submitting the Identity form even when the entered values were valid.

V2.0.1 changes every affected wizard to use a user-locked ephemeral continuation button between modal steps:

- Player creation: Identity -> `Continue — Stats 1/2` -> Stats 1 -> `Continue — Stats 2/2` -> Stats 2
- Player stat reallocation: Stats 1 -> continuation button -> Stats 2
- Admin `/boxer_create_wizard`: Basics -> continuation button -> Stats 1 -> continuation button -> Stats 2

The continuation controls can only be used by the Discord user who started that workflow. No boxer is written until the final valid 60-point build is submitted.

The screenshot values `66.7`, `Male`, and `Iron Body` were already valid and were not the cause of the error.

## Additional runtime fix

`boxing_bot/cogs/roster.py` used `boxer_embed(...)` without importing it. The missing import is restored so the admin roster creation/view paths do not fail after a successful operation.
