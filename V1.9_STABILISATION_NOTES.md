# BoxingBot V1.9 Stabilisation

This build is the hardened baseline intended to precede BoxingBot V2.

## Critical fixes
- Restored missing `_summary_embed()` used by completed-fight flows.
- Repaired fight persistence and restart recovery using `fight_sessions.json`.
- Added per-channel serialized fight actions so `/start`, `/fight`, `/next_round`, and `/resolve_test` cannot mutate one fight concurrently.
- Repaired dormant fight repository/autosave code that called nonexistent DB APIs.
- Hardened boxer DB writes with atomic replace and corrupt-file preservation instead of silently starting fresh.
- Fixed `/next_round` so it cannot continue into a phantom Round 13 after the 12-round decision gate.
- Persist fight state immediately after round logs, finish state, and round advancement.

## Combat integrity
- Preserved corrected damage/KD ownership used by points scoring.
- Scorecards are deterministic and cached: recomputing a decision cannot change judge cards.
- Judge scoring no longer consumes the live fight RNG.
- Knockdowns materially influence who wins a round even when raw damage points the other way.
- Three-knockdown rule stops the round immediately on the threshold KD.
- Trait/special to-hit effects are applied before the decisive hit check so marginal rolls can actually be changed by those effects.
- Fight-critical hit-type and location selection now uses the session RNG.
- Fight sessions use a stored 64-bit seed for reproducibility.
- Existing damage-based TKO rule remains: HP <= 5, or HP <= 10 with >=20 damage received in that round.
- Foul deductions remain round-specific.

## Discord/UI hardening
- Boxer creation wizard split into valid 4+4 stat modal pages (Discord maximum is five modal components).
- Restored the intended 60-point base-stat cap consistently across slash creation, wizard creation, current DB, and Google Sheet imports.
- Boxer/promo selectors now paginate rather than exceeding Discord's 25-option select limit.
- Roster mutation, match-control, voice-stop/promo-stop, and sheet-import actions require administrator permission.
- Global command sync is performed once per process instead of on every reconnect.
- Missing `DISCORD_TOKEN` now fails fast with a clear startup error.

## Audio/media
- Commentary can interrupt crowd ambience so commentary is not silently skipped; ambience resumes via its loop.
- Commentary clips play to natural completion unless a duration is explicitly requested.
- FFmpeg playback and diagnostics use the same PATH/config resolution model.
- `Settings.MUSIC_DIR` compatibility added for old fallback code.
- Legacy machine-specific intro music paths are normalized by filename; current DB paths are portable.
- Runtime asset discovery no longer depends on the current working directory.
- Generated promo/composite images are cleaned after sending.

## Security/config/dependencies
- Inline Google service-account JSON is loaded directly in memory instead of being written to a persistent temp file.
- Dependencies are bounded in `Requirements.txt` for a reproducible V1.9/V2 baseline.
- `.env`, old virtual environments, IDE metadata, caches, and compiled Python files are excluded from the clean package.
- `.env.example` is included.

## Data/model consistency
- Weight-class calculation now includes lightweight, light-heavyweight, and cruiserweight instead of jumping directly through the old reduced set.
- Weight-class modifier keys consistently use `defense`.
- Existing roster validated at 60 base points per boxer.

## Verification performed
- All 34 Python source files AST-parse and compile.
- JSON files parse successfully.
- Six combat regression checks pass:
  1. scoring ownership/direction
  2. 10-point-must + knockdowns
  3. round-specific foul deduction
  4. KD affects round outcome when damage trails
  5. scorecards remain immutable/deterministic
  6. TKO thresholds
- Fight-session serialize/restore round-trip passes including RNG state.
- Known blocker searches (`db.read`, `db.write`, `os.getcwd`, placeholder token fallback) are clear.

## Environment limitation
A full live Discord/voice handshake was not possible inside the build container. The archived Windows `.venv` contains Windows-native `audioop`/Pillow binaries and cannot be executed in this Linux environment, while the clean environment has no network access to install discord.py. Therefore Discord API registration and live FFmpeg/voice behaviour still need one local smoke test on the machine that runs the bot.

## Assets not present in this source package
The code references media that is not present in the reconstructed archive: all 42 configured round-highlight GIFs, the base ring/round GIFs, and three generic judge fallback images. Specific judge images and a substantial commentary/music set are present. Missing media is handled through existing fallback behaviour; no replacement art was fabricated in V1.9.
