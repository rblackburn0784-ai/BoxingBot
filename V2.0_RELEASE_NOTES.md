# BoxingBot V2.0 — True V2 Release

V2.0 keeps the stabilised V1.9 fight engine but rebuilds the surrounding bot into a persistent Discord boxing game.

## Player game layer
- `/menu` is the primary player surface.
- One linked boxer per Discord user per guild.
- Players can create their own boxer from the menu.
- Players can edit identity/intro/trait/weight and reallocate stats outside active tournaments.
- Boxer profiles persist career W-L-D, KO/TKO/points wins, KDs, damage, streaks, tournament entries/titles/runner-up finishes, XP, level, prestige, title and achievements.
- Fight history, career profiles, head-to-head cards and leaderboards are persistent.
- Grudge challenge flow: issue → opponent accepts → admin stages fight → completed bout closes the challenge automatically.

## Fair-play rules
- Every V2 boxer uses exactly 60 base points.
- Maximum 20 in any base stat.
- Every boxer starts each fight with exactly 100 HP.
- XP/levels/prestige/titles/achievements never add combat stats.
- Weight classes remain meaningful for identity/divisions but no longer grant free combat stat points.
- Tournament registration stores a locked stat/trait/weight snapshot; tournament fights use that snapshot even if the live profile changes later.
- Legacy/admin boxer creation and Google Sheet imports are subject to the same 60-point / 20-per-stat legality rules.

## Tournament game layer
- Persistent SQLite tournament records.
- Registration mode with player self-entry and admin-managed/offline boxer entry.
- 2–64 entrant single-elimination tournaments.
- Deterministic bracket shuffle using tournament seed/id.
- Odd fields receive automatic byes.
- Tournament Director dashboard with current round, next bout, entrants and live tournament stats.
- Fight completion automatically records the career result and advances the matching tournament bout.
- Champion and runner-up are stored permanently.
- Tournament-specific achievements, statistics and awards/leaders are stored or derived permanently.
- Completed tournaments remain accessible through Tournament Archive and `/tournament_show`.

## Admin menu hierarchy
- Boxer Management
- Tournament Control
- Match Control
- Records & Awards
- Bot Settings / diagnostics
- Admin Home navigation from submenus.

## Reliability / persistence
- New `boxing_v2.sqlite3` career/game database with foreign keys and WAL mode.
- Transactional writes and idempotent fight result keys prevent duplicate career results after Discord retries/reconnects.
- Automatic SQLite backup on startup plus manual Backup Database button.
- Existing V1.9 active-fight JSON recovery remains in place.
- Audit log records important V2 ownership/tournament actions.
- Legacy `boxing_db.json` remains the canonical boxer combat-definition store for V2.0, and boxer profiles are imported into SQLite automatically on startup.

## Compatibility
- Existing V1.9 admin slash commands remain available as compatibility shortcuts.
- Existing fight presentation/audio/combat code is retained rather than rewritten without live Discord testing.
- Current boxer database is migrated non-destructively; existing boxers begin with a fresh V2 career record unless V2 records already exist.

## New commands
- `/menu`
- `/career [boxer]`
- `/fight_preview red blue`
- `/tournament_show tournament_id`
- `/v2_link_boxer boxer user` (admin)

The original `/start`, `/fight`, `/next_round`, promo, roster and maintenance commands remain available.
